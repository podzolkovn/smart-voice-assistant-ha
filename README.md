# Smart Voice Assistant for Home Assistant

Голосовой ассистент для Home Assistant на Raspberry Pi 4. Принимает голосовые команды на русском языке, управляет умными устройствами, воспроизводит музыку и отвечает на вопросы о погоде, времени и состоянии дома.

---

## Оборудование и стек

| Компонент | Решение |
|---|---|
| Железо | Raspberry Pi 4 |
| Платформа | Home Assistant (Supervised) |
| Wake word | Hey Jarvis (Linux Voice Assistant) |
| STT | GroqCloud Whisper |
| NLP | pymorphy3 + rapidfuzz |
| TTS | Piper (Wyoming) |
| Музыка | Music Assistant + Яндекс Музыка |

## Архитектура

Интеграция реализована как `custom_component` с паттерном DDD — каждый слой отвечает за свою область.

```
custom_components/smart_assistant/
├── __init__.py                  — регистрация интеграции в HA
├── config_flow.py               — настройка через UI
├── conversation.py              — главный агент, точка входа всех команд
├── query_handler.py             — ответы на вопросы (погода, время, дата, дом)
└── nlp/
    ├── morphology.py            — лемматизация через pymorphy3
    ├── fuzzy_matcher.py         — нечёткий поиск устройств через rapidfuzz
    ├── action_matcher.py        — роутинг команд, извлечение действий
    └── dictionaries/
        ├── actions.py           — синонимы действий, уровни громкости
        ├── keywords.py          — ключевые слова для роутинга
        ├── media.py             — ключевые слова и типы медиа
        ├── modes.py             — режимы устройств, цвета, эффекты ламп
        └── stop_words.py        — стоп-слова для парсинга
```

### Пайплайн обработки команды

```
Голос → Hey Jarvis (wake word)
      → GroqCloud Whisper (STT) → текст
      → conversation.async_process()
          → re.sub() — очистка пунктуации
          → split_commands() — разбивка на части (и/потом/затем)
          → normalize_text() — лемматизация через pymorphy3
          → detect_command_type() — роутинг:
              "query"       → query_handler.handle_query()
              "state_query" → _handle_state_query()
              "music"       → _handle_music() / _handle_volume()
              "device"      → _handle_device()
      → TTS ответ через Piper
```

### Роутинг команд (`detect_command_type`)

| Тип | Триггер | Обработчик |
|---|---|---|
| `query` | погода, прогноз, время, день, дата, температура, влажность... | `handle_query()` |
| `state_query` | какой, какая, состояние, статус, включён... | `_handle_state_query()` |
| `music` | музыка, громкий, тихий, громкость, остановить... | `_handle_music()` / `_handle_volume()` |
| `device` | всё остальное | `_handle_device()` |

> Таймер намеренно отдан HA Default Agent — он обрабатывает прописные числа ("на одну минуту") и управляет сигналом нативно.

| громче / тише | volume_up / volume_down (шаг) |
| громкость [число] / [число]% | volume_set 0–100% |
| максимальная / минимальная громкость | volume_set 100% / 10% |
| средняя громкость | volume_set 50% |

#### Как работает музыка на Яндекс станции

Интеграция AlexxIT/YandexStation не поддерживает стандартные HA-сервисы (`media_pause`, `media_stop`). Все команды отправляются через:

```python
media_player.play_media(
    entity_id="media_player.yandex_station_l00sbr700pytvb",
    media_content_id="включи мою волну",  # оригинальный текст команды
    media_content_type="command"           # Алиса выполняет как голосовую команду
)
```

Текст команды передаётся **до лемматизации** (оригинал), иначе Алиса получит сломанную речь.

## NLP: как работает лемматизация

Все входящие токены приводятся к нормальной форме через pymorphy3 перед сравнением со словарями. Словари содержат именно нормальные формы.

| Сказал | Лемма | Словарь |
|---|---|---|
| громче / погромче | громкий | VOLUME_KEYWORDS |
| тише / потише | тихий | VOLUME_KEYWORDS |
| прибавь | прибавить | VOLUME_KEYWORDS |
| убавь | убавить | VOLUME_KEYWORDS |
| замолчи | замолчать | MEDIA_STOP_KEYWORDS |
| останови | остановить | MEDIA_STOP_KEYWORDS |
| включи | включить | BASE_SYNONYMS |
| выключи | выключить | BASE_SYNONYMS |

Поиск устройств — нечёткий через rapidfuzz (`partial_ratio`, порог 60). Это позволяет находить устройства по неточному названию.

## Важные нюансы

**Пунктуация** — wake word иногда приходит с пунктуацией ("эй, джарвис!"). Очищается через `re.sub(r"[^\w\s]", " ", text)` до токенизации.

**Wake word фильтр** — если команда состоит только из слов `{"эй", "джарвис", "jarvis", "hey"}` — возвращается пустой ответ без обработки.

**None в ответах** — каждый обработчик возвращает `str | None`. `None` идёт в `failed`, строка в `executed`. `join()` вызывается только на непустых списках.

**Music Assistant обёртки** — у каждого устройства два entity: нативный и MA-обёртка. Команды нужно отправлять на **нативный**, иначе MA перехватывает и пытается искать трек в своей библиотеке.

| Устройство | Нативный ✅ | MA-обёртка ❌ |
|---|---|---|
| Яндекс Лайт | `media_player.yandex_station_l00sbr700pytvb` | `media_player.iandeks_lait` |
| Pi динамик | `media_player.pi_assistant_media_player` | `media_player.pi_assistant_media_player_2` |
